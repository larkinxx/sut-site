# Сервер INNSIDER

Сайт — статический (Timeweb App Platform, пересобирается сам при пуше в `main`). API и данные ФНС — облачный сервер
Timeweb `5.129.207.51` (Ubuntu 24.04, служба `sut-api`, база ФНС `/var/lib/sut/fns.db`, архивы `/var/lib/sut/opendata`).
Владелец — не программист: пиши ему по-русски, простыми словами, без канцелярита; команды давай целиком и по одной.

## Как попасть на сервер

Из облачной сессии SSH невозможен (прокси пропускает только TLS). Всё делается задачей GitHub Actions
**«Сервер: команда»** (`.github/workflows/server.yml`) через GitHub MCP:

1. `actions_run_trigger` → `run_workflow`, `workflow_id: server.yml`, `ref: main`, `inputs: {"action": "<действие>"}`.
2. `actions_list` → `list_workflow_runs` (`resource_id: server.yml`, `perPage: 1`) → id запуска;
   `list_workflow_jobs` → id задачи; дождаться `status: completed`.
3. `get_job_logs` (`job_id`, `return_content: true`, `tail_lines: 30`).

Запускай действия **по одному и дожидайся завершения**: у задачи `concurrency: server-ops` без отмены, и новый запуск,
поставленный в очередь, вытесняет ещё не начатый предыдущий.

Действия (`deploy/ops.sh`, на сервере — копия `/usr/local/sbin/sut-ops`):

| Действие | Что делает |
|---|---|
| `status` | версия кода, службы сайта и импорта, последние строки журнала импорта, число строк в таблицах ФНС, диск и память |
| `import` | запускает импорт ФНС отдельной службой `fns-import` (не зависит от SSH); если уже идёт — не запускает второй |
| `peers` | только пересчёт статистики похожих компаний по уже загруженным данным (служба `fns-peers`, пара минут) — после исправлений в `scripts/fns-peers.mjs`, когда все наборы уже загружены |
| `import-stop` | останавливает импорт и распаковщик |
| `update` | `git pull` от пользователя `sut` и перезапуск сайта — выложить слитые в `main` изменения сервера |
| `archive-check` | архивы ФНС на диске и строки журнала про скачивание и битые файлы |

Репозиторий публичный — лог задачи видят все. Не добавляй в `ops.sh` вывод журналов сайта, данных пользователей, секретов.
Изменения `ops.sh` начинают работать только после того, как владелец под root переустановит копию (`deploy/README.md`),
`status` пишет «установленная копия отличается» — попроси владельца выполнить `install …` из README.

## Импорт ФНС

`scripts/fns-import.mjs` качает наборы `https://www.nalog.gov.ru/opendata/7707329152-<набор>/` (snr, sshr2019, paytax,
debtam, revexp, rsmp), кладёт в SQLite и затем считает статистику похожих компаний (`scripts/fns-peers.mjs` → `fns_peers`,
`fns_market`). По расписанию — cron 26-го числа; вручную — действие `import`. Уже загруженный архив повторно не качается.

Порядок после слияния PR, который меняет импорт: `update` → дождаться → `import` → через 15–20 минут `status`
(для долгих ожиданий — `send_later`, не `sleep`).

Что в журнале нормально:
- `rsmp: 100000`, `200000`… — ход разбора (реестр МСП — около 2 ГБ, миллионы записей, ЮЛ ≈ 2–3 млн);
- `контрольная сумма не совпала — перепроверяю все N частей` и `заменено частей: K` — скачивание частями нашло
  испорченные при передаче части и заменило их;
- `часть файлов архива повреждена, загружено остальное — … ИТОГО файлов N, битых M` — пропущены битые файлы (≤ 1%).

Готово, когда `status` показывает `импорт ФНС inactive`, в журнале `Статистика похожих компаний: N групп`,
а `fns_msp` и `fns_peers` больше нуля — тогда на сайте работают калькулятор `/kalkulyatory/perspektivy-biznesa/`
и блок «Среди похожих компаний» в проверке по ИНН.

## Типовые ошибки

| В журнале | Причина и что делать |
|---|---|
| `terminated` при скачивании | `file.nalog.ru` рвёт соединение ≈ через 5 минут. Большие архивы качаются частями (`downloadRanged`) — не должно быть; если есть, смотри, почему не сработал HEAD/Range |
| `контрольная сумма не совпала` несколько кругов подряд, затем `испорчен у ФНС` | копии частей совпадают, но ETag не сходится: либо архив у ФНС битый, либо портит канал сервера. Проверить скачивание с другой машины; ждать нового выпуска |
| `архив повреждён (4)` | битых файлов > 1% или архив не читается; архив удалён, следующий `import` скачает заново |
| `нет нужных полей — формат изменился?` / `ни одной записи` | ФНС поменяла структуру XML (номер структуры в имени архива) — сверить теги в `DATASETS` с реальным файлом |
| `database is locked` | идёт другой импорт; `import-stop`, затем `import` |
| служба `sut-api` не `active` после `update` | ошибка в коде сервера: смотреть последний PR, откатить или исправить, снова `update` |

## Перед тем как менять код сервера

`npm run test:server` и `npm run check` должны проходить. Большие архивы в тестах не нужны: в `server/test-fns.mjs`
есть заглушки — локальный HTTP-сервер с Range/ETag и сборка zip без внешних утилит (`makeZip`).
